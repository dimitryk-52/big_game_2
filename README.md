# BIG GAME 2 ビッグゲーム 2

Пиксельная викторина-«конкистадор» по Японии для вечеринки. ТВ показывает карту и вопросы, каждый игрок отвечает со своего телефона, ведущий управляет игрой и наполняет базу вопросов.

| Страница | Для кого | Где живёт |
|---|---|---|
| `tv.html` | Экран на ТВ. Здесь же работает «мозг» игры (хост) | только локально |
| `admin.html` | Ведущий: вопросы, награды префектур, настройки, пульт | только локально |
| `play.html?room=XXXX` | Телефон игрока (вертикально, Android и iPhone) | GitHub Pages (и локально) |

На GitHub Pages публикуется **только страница игрока**. ТВ и админка запускаются на компьютере ведущего (`npm run local`) и общаются с телефонами через Supabase.

## Быстрый старт (без Supabase, по Wi-Fi)

```bash
npm install
npm run dev
```

1. Vite выведет адрес вида `Network: http://192.168.1.23:5173/`. Открой на ТВ/ноутбуке **именно сетевой адрес**: `http://192.168.1.23:5173/tv.html`.
2. Нажми «Новая игра». Телефоны сканируют QR-код (они должны быть в той же Wi-Fi сети).
3. Для теста без людей: `tv.html?bots=3` добавит трёх ботов.

В dev-режиме сообщения идут через встроенный ретранслятор Vite, а вопросы и настройки хранятся в папке `.devdata/`.

## Боевой режим: Supabase + GitHub Pages

1. Создай проект на [supabase.com](https://supabase.com) (хватит бесплатного тарифа).
2. Открой **SQL Editor**, вставь и выполни `supabase/schema.sql`. Он создаст таблицы `questions` и `kv` и публичный bucket `media` для картинок.
3. Возьми **Project URL** и **anon / publishable key** в Project Settings → API.
4. Локально: скопируй `.env.example` в `.env` и заполни значения.
5. GitHub: Settings → Secrets → Actions, добавь `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Settings → Pages → Source: **GitHub Actions**. Каждый push в `main` публикует страницу игрока (`.github/workflows/deploy.yml`, сборка с `PAGES=1`; корень сайта перенаправляет на `play.html`).
6. Бесплатный проект Supabase засыпает примерно после недели без активности. Перед игрой зайди в дашборд и разбуди его.

### Запуск игры: ТВ и админка локально, телефоны — через GitHub Pages

ТВ и админка работают на компьютере ведущего и общаются с телефонами через Supabase.

**Проще всего:** двойной клик по `Запустить ТВ.bat` или `Запустить админку.bat` в папке проекта. Откроется чёрное окно с сервером и браузер с нужной страницей. Пока окно открыто, игра работает. Если сервер уже запущен одним файлом, второй просто откроет свою страницу.

Вручную то же самое — в терминале в папке проекта:

1. В `.env` должны быть `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` и `VITE_PUBLIC_URL` (адрес GitHub Pages, например `https://dimitryk-52.github.io/big_game_2/`).
2. `npm run local` — соберёт проект и откроет `http://localhost:4173/tv.html`. Админка: `http://localhost:4173/admin.html`. Можно и `npm run dev` (порт 5173).
3. QR-код на ТВ ведёт телефоны на `play.html` на GitHub Pages, а сам ТВ работает с твоего компьютера.

Телефонам всё равно нужен публичный адрес: открыть `localhost` твоего компьютера они не могут. Поэтому `play.html` живёт на GitHub Pages.

Режим сети можно переопределить параметром URL: `?net=supabase | ws | local`.

## Архитектура

```
 Телефоны ──(input: ответы, выборы)──►  ТВ (хост, движок игры)
    ▲                                       │
    └──────(game: состояние)────────────────┘      Supabase Realtime Broadcast
                                            │
                                            └─► Postgres: вопросы, настройки, снапшот игры
```

- **Хост — вкладка ТВ.** Она единственный источник правды: ведёт сценарий, таймеры и случайность. Телефоны — «пульты».
- **Каналы.** `game` (хост → все) и `input` (телефоны → хост). На `input` подписан только хост, а телефоны шлют туда через REST (`httpSend`). Поэтому ответ игрока доставляется одному получателю, а не всем десяти.
- **Состояние шлётся частями.** Уходят только изменившиеся куски (`players`, `q`, `stage`…). Ответ игрока — это маленький пакет `q`, а не вся игра.
- **Postgres Changes не используется.** В базу пишем только снапшот (не чаще раза в 1,5 с, на контрольных точках) и вопросы.
- **Честное время.** Телефон синхронизирует часы с хостом по принципу NTP (серия пингов, берутся замеры с минимальной задержкой). Дедлайны задаются в часах хоста, ответ несёт метку времени нажатия в часах хоста. Медленный интернет не крадёт секунды.
- **Мини-игры играются на телефоне.** На сервер уходят только разовые события:
  - **Пачинко.** Детерминированная физика (только `+ − × ÷ √`, фиксированный шаг): траектория шарика полностью задаётся `(seed, сила)`. Телефон раз в секунду шлёт пачку запусков, ТВ воспроизводит ту же анимацию в окне PnP. Деньги списывает и начисляет хост.
  - **Призовое кольцо.** Старт (seed и время старта) выдаёт хост. Телефон шлёт время нажатия «СТОП» в часах хоста, результат считает хост.
  - **Ритм-баттл.** Музыка синтезируется на ТВ (WebAudio) и стартует в момент, заданный в часах хоста. Ноты падают на телефоне по тем же часам, окно попадания ±150 мс (вариант C). В настройках есть поправка на задержку звука ТВ (Bluetooth-саундбар).

### Оценка лимитов Supabase Free

Прогон движка с 5 ботами (`npm run sim`): около **1000 сообщений и 0,9 МБ за 30 минут игры**. Каждое сообщение канала `game` доставляется примерно 11 получателям, это около 11 000 доставок за полчаса. Трёхчасовая игра на 10 человек даст порядка **100–150 тыс.** доставок при лимите 2 млн в месяц. Подключений около 12 при лимите 200.

Где может уйти трафик:
- **Картинки в вопросах** идут и на телефоны, поэтому загружаются в Storage. При загрузке их сжимает до webp ~900px, это десятки КБ на картинку.
- **Пульт в админке** подписан на состояние, как ещё один телефон. Держи его открытым только когда нужен.

## Правила (как реализовано сейчас)

1. **Калибровка.** `calibRounds` кругов по боевым темам (музыка, культура, география). Отвечают все, верный ответ даёт +1 к силе темы. Сила = 1 + очки.
2. **Порядок ходов.** От слабого к сильному (по сумме силы, ничья — жребий), фиксируется до конца игры.
3. **Высадка.** Пошагово, от сильного к слабому. Каждый выбирает префектуру на телефоне и видит выборы других. Нельзя на занятую и соседнюю с занятой. Таймер истёк — случайная разрешённая префектура.
4. **Ход.** Только на соседнюю префектуру, стоять нельзя. Бонус 👟 позволяет пойти на 2. В префектуре максимум 2 игрока. Туман общий и открывается при заходе.
5. **Вопрос префектуры.** Отвечают все. Ходящий: верно — йены + звезда + награда префектуры, неверно — немного йен. Остальные за верный ответ получают меньше. Вернуться в префектуру можно, физический приз выдаётся один раз.
6. **Бонусы.** Перед вопросом даётся 5 с на выбор (−1 ответ, 50/50) или «Не хочу». В дуэли сначала выбирает атакующий, потом защитник.
7. **Дуэль**, если закончил ход рядом с другим игроком. Атакует пришедший. До `duelRounds` раундов, в каждом оба по очереди выбирают тему (или 💥 спецвопрос, или 🥁 ритм-баттл) и отвечают оба. Если ответы расходятся, ошибившийся получает урон, равный силе темы у ответившего верно. Спецвопрос бьёт с силой 5, если верно ответил задавший. Оба верно или оба неверно — урона нет.
8. **Воскрешение.** Если HP = 0, в начале следующего хода игрок получает вопрос про Окинаву. Верно — HP полностью и бонус с йенами, неверно — просто HP полностью. После этого он сразу ходит.
9. **Магазин** на телефоне, доступен в любой момент: спецвопрос, +HP, +1 к силе темы, бонусы.
10. **Пачинко и призовая машина** работают в префектурах, отмеченных в админке. Когда начинается вопрос, автомат честно встаёт на паузу.

## Ведущему

- Клавиши на ТВ: **Пробел** — далее (пропустить ожидание), **P** — пауза, **F** — полный экран, **H** — скрыть панель.
- Игра идёт сама. Она ждёт только выбора хода игроком. Если игрок «завис», жми «Далее» — ход будет случайным.
- Пульт (`admin.html` → Пульт) умеет: старт, далее, пауза, выдать йены/звёзды/HP/приз, переместить или удалить игрока, перечитать вопросы и настройки в идущей игре.
- Если упал ТВ: открой `tv.html` снова и нажми «Продолжить игру». Игра продолжится с начала текущего хода.
- Если упал телефон игрока: открой ссылку снова, вход восстановится автоматически. С другого устройства: «Я уже в игре», имя и 4-значный PIN (он показан на главном экране игрока).

## Вопросы

- В админке: текст, тема, привязка к префектуре, спецвопрос, своё время, медиа (картинка — на ТВ и телефоне, аудио и видео — только на ТВ), ответы текстом или картинками (на телефоне сетка 2×2).
- **Аудио и видео никуда не загружаются.** Положи файлы в папку `media/` в проекте (можно по подпапкам), а в вопросе укажи только имя файла, например `kurenai.mp4`. Админка подсказывает имена из папки. Локальный сервер (`npm run local` / `npm run dev`) сам раздаёт их ТВ, выбирать ничего не нужно. Значок 🎬 на панели ТВ показывает, сколько файлов в папке и каких из вопросов не хватает (клик — обновить). Папка `media/` не попадает в git.
- Тема `general` — запасные вопросы для префектур без своих вопросов, тема `okinawa` — вопросы воскрешения.
- Импорт и экспорт в JSON. Пока база пустая, используется стартовый набор (~90 вопросов, `src/shared/seedQuestions.ts`).

## Разработка

```bash
npm run dev        # dev-сервер + ретранслятор
npm run build      # проверка типов + сборка в dist/
npm run sim        # headless-прогон движка с ботами
npm run build:map  # пересборка карты из src/img/map.png (python scripts/build-map.py [--debug папка])
npm run build:bgs  # фоны префектур: src/img/bgs/bg_*_orig.png → пиксель-арт bg_*.png (python scripts/pixelart.py --bgs)
```

Карта — рисунок `src/img/map.png` (46 префектур без Окинавы). `scripts/build-map.py` находит на нём границы префектур (толстые чёрные линии) и заливает их от «зёрен» из `scripts/map-seeds.json` — по точке-другой на префектуру в пикселях рисунка. Результат: `src/map/assets/map.webp` (рисунок без потерь), `src/map/assets/regions.png` (маска префектур для тапов, тумана и подсветки) и якоря/рамки в `src/map/japan.json`. Если префектура легла не туда — поправь точки в `map-seeds.json`, запусти с `--debug папка` и посмотри `regions-debug.png`. Соседство для ходов — по реальной географии (поле `adj` в `japan.json`, с морскими связями), скрипт только печатает расхождения с рисунком. Нужны Python-пакеты pillow, numpy, scipy, scikit-image.

Пиксель-арт: нейросеть рисует «мыльные» пиксели разного размера, поэтому `scripts/pixelart.py` уменьшает картинку до родной сетки (клетка `--cell`, по умолчанию 3 пикселя исходника) и берёт в каждой клетке самый частый цвет палитры. В игре картинка растягивается без сглаживания и остаётся чёткой. Карта собирается так автоматически (`build:map`). Новые фоны префектур кладутся как `src/img/bgs/bg_<префектура>_orig.png` (1024×1024), потом `npm run build:bgs`. Фон показывается под вопросом и в интро префектуры: на ТВ вырезается полоса во всю ширину по центру, на телефоне — во всю высоту.

Иконки — PNG в `src/img/icons/`, их можно рисовать в любом пиксельном редакторе (Aseprite, Piskel, Paint.NET): прозрачный фон, один пиксель файла — один пиксель иконки, размер 9–12 px. Чёрный контур и тень игра добавляет сама. Имена: `money`, `stars`, `bonus`, `special`, `prize` (награды префектур, на карте и в интерфейсе), `pachinko`, `ring` (автоматы на карте), `topic_<id темы>` (скиллы: `topic_music`, `topic_culture`, `topic_geo`; для темы без файла рисуется ромб её цвета). После сохранения файла страница обновится сама (`npm run dev`). Персонажи пока рисуются кодом в `src/shared/sprites.ts` (массив `BASE` и шляпы `HATS`), эмодзи на кнопках телефона — прямо в разметке.

UI-кит: все элементы интерфейса (кнопки, ответы, полоски, панели, плашки, иконки, персонажи, сообщения ТВ, интро) собраны на странице `ui.html`: после «Запустить ТВ.bat» — `http://localhost:4173/ui.html`, в `npm run dev` — `http://localhost:5173/ui.html` (двойной клик по файлу не сработает, нужен сервер). Стиль — `src/styles/kit.css`: тёмный контур в «пиксель» (`--px`), срезанные углы, светлая полоса сверху и тёмная снизу; цвет кнопки — переменная `--c`, рамки панели — `--frame`.

Музыка: положи `music/map.mp3` (карта, играет всю игру) и `music/duel.mp3` (дуэль) в папку `music/` в корне проекта. Файлы только локальные, в git не попадают; играют на ТВ, тише во время вопросов, молчат в ритм-батле и в вопросах с аудио/видео. Нет файла — без музыки.

Новые фоны префектур (`src/img/bgs/bg_*_orig.png`) батники «Запустить ТВ/админку» превращают в пиксель-арт сами при запуске.

Логотип: `src/img/logo.png` → `npm run build:logo` делает `logo_menu.webp` для меню; если положить `src/img/logo_text.png`, рядом появится пиксельный `logo_text_px.png` для угла ТВ.

Отладка: кнопка 🐞 на пульте ТВ; на телефоне — `play.html?debug=1` или 5 быстрых тапов по своему аватару (так же выключается) показывает любой экран игры сразу на ТВ и телефонах: вопросы, интро, награды, дуэль, ритм, финал. Сценарий игры при этом не трогается.

Шрифт — [DotGothic16](https://fonts.google.com/specimen/DotGothic16): пиксельный, с кириллицей, латиницей и японским.

## Генератор пиксель-арта (Nano Banana)

Локальная страница для генерации спрайтов через Gemini. В `.env` добавь `GEMINI_API_KEY=...`
(ключ из Google AI Studio, **без** префикса `VITE_`), затем запусти «Пиксель-арт.bat» или `npm run pixelart`
и открой http://localhost:4180. Ключ остаётся на локальном сервере и в браузер не передаётся.

Модель рисует «псевдо-пиксели» с мылом по краям, поэтому справа от оригинала показан обработанный вариант:
сведение к сетке 16–128 клеток, сокращение палитры, вырезание однотонного фона (для этого по умолчанию
просим пурпурный фон). «Сохранить в проект» кладёт PNG в `tools/pixelart/out/` (папка в .gitignore).
